The issue is in the `renderEditInput` function (line ~308) and the `buildDiffHunks` function (line ~376). The problem: when `old_string` and `new_string` are present but `buildDiffHunks` returns empty hunks (because the LCS algorithm treats the strings as equal when they only differ by whitespace or a single line), the diff shows "no changes" even though there ARE changes.

**Root cause analysis:** The `buildDiffHunks` function at line 376 does an LCS diff. It checks `if (changeIndexes.length === 0) return [];` at line 425. The `UnifiedDiff` component then checks `const hasChanges = oldText !== newText;` (line 503) which correctly detects a difference, but if hunks array is empty it falls through to show "No changes detected" message. The actual problem is that the LCS algorithm can fail for certain inputs.

**Fix approach - make the diff more robust:**

1. In the `renderEditInput` function (line ~308), change the condition for showing the diff. Currently it checks `if (oldString || newString)` which shows UnifiedDiff. The issue is when BOTH are present but nearly identical. Keep this logic but ensure `UnifiedDiff` always produces visible output.

2. In `buildDiffHunks` function, add a **fallback** after the LCS diff. After computing `ops` from the LCS walk (line ~419), check: if `changeIndexes.length === 0` BUT `oldText !== newText`, this means the LCS algorithm failed to detect differences. In this case, fall back to a simple line-by-line comparison:
   - Split both texts by newline
   - For each line index, compare oldLines[i] vs newLines[i]
   - If they differ, mark the old line as 'remove' and new line as 'add'
   - Handle different-length arrays by marking extra lines in the longer array

   Replace the early return at line 425 (`if (changeIndexes.length === 0) return [];`) with:
   ```typescript
   if (changeIndexes.length === 0) {
     // LCS found no changes, but caller detected a difference.
     // Fall back to simple line-by-line diff.
     if (oldText !== newText) {
       const allOps: Array<{ type: 'context' | 'remove' | 'add'; text: string }> = [];
       const maxLen = Math.max(oldLines.length, newLines.length);
       for (let k = 0; k < maxLen; k++) {
         const oldLine = k < oldLines.length ? oldLines[k] : undefined;
         const newLine = k < newLines.length ? newLines[k] : undefined;
         if (oldLine === newLine) {
           allOps.push({ type: 'context', text: oldLine! });
         } else {
           if (oldLine !== undefined) allOps.push({ type: 'remove', text: oldLine });
           if (newLine !== undefined) allOps.push({ type: 'add', text: newLine });
         }
       }
       // Build a single hunk from all ops
       let oLineNo = 0;
       let nLineNo = 0;
       const lines: DiffLine[] = allOps.map((op) => {
         if (op.type === 'context') {
           oLineNo++; nLineNo++;
           return { type: 'context' as const, text: op.text, oldLine: oLineNo, newLine: nLineNo };
         }
         if (op.type === 'remove') {
           oLineNo++;
           return { type: 'remove' as const, text: op.text, oldLine: oLineNo };
         }
         nLineNo++;
         return { type: 'add' as const, text: op.text, newLine: nLineNo };
       });
       const oLen = allOps.filter(o => o.type !== 'add').length;
       const nLen = allOps.filter(o => o.type !== 'remove').length;
       return [{ header: `@@ -1,${oLen} +1,${nLen} @@`, lines }];
     }
     return [];
   }
   ```

3. Also add a safety check in `UnifiedDiff` component: if `hasChanges` is true but `hunks` is empty (shouldn't happen anymore but as a safety net), show the old and new text side by side using CollapsibleDiff components as a fallback, rather than showing "No changes detected":
   ```typescript
   {hasChanges && hunks.length === 0 ? (
     <>
       <CollapsibleDiff title="Old" content={oldText} variant="old" />
       <CollapsibleDiff title="New" content={newText} variant="new" />
     </>
   ) : hasChanges ? hunks.map(...) : (
     <div>No changes detected</div>
   )}
   ```
