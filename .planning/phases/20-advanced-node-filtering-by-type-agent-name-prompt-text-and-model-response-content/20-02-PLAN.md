  <action>
Transform each filter chip in the Toolbar's filterGroup section to support content-level filtering. Current behavior: click toggles category visibility. New behavior: click still toggles visibility, but each chip also has an expandable text input for content filtering.

**UI design:**
1. Each chip retains its click-to-toggle behavior for category visibility (existing `toggleNodeTypeVisibility`).
2. Add a small filter icon or right-click/secondary interaction to open a text input below or beside the chip. Simplest approach: when a category is visible (not hidden), show a small text input field below the filter chip group, or inline next to the chip.
3. Recommended implementation: Use a small dropdown/popover triggered by a filter icon on each chip. When clicked, shows a compact text input below the chip. Use component-local useState for which category's filter input is open (`activeFilterInput: string | null`).
4. The text input should:
   - Read current value from `nodeTypeFilters.get(category) || ''`
   - On change, call `setNodeTypeFilter(category, value)`
   - Show a placeholder like "Filter by name..." for tools, "Filter by agent..." for agents, "Filter by text..." for prompts/model
   - Include a small "x" clear button when a filter is active
5. When a category has an active content filter (non-empty string in nodeTypeFilters), show a visual indicator on the chip — e.g., a small colored dot, underline, or different background shade.
6. Read `nodeTypeFilters` from the store: `useSessionStore((state) => state.nodeTypeFilters)`
7. Read `setNodeTypeFilter` and `clearNodeTypeFilter` from the store.

**Styling:**
- Filter input should be compact (150-200px wide, small font)
- Position below the filter chip row or as a dropdown
- Match existing dark theme (#16213e background, #0f3460 borders, #eee text)
- Use absolute positioning for dropdown to avoid layout shift
- Close dropdown when clicking outside (can reuse useClickOutside pattern from existing codebase)

**Implementation detail for the dropdown approach:**
- Each chip gets a small "funnel" icon (or down arrow) next to the label, only visible when category is not hidden
- Clicking the funnel opens a small dropdown panel below the chip with a text input
- The chip itself still toggles visibility on click (left portion)
- Split the chip into: label area (click = toggle) and filter icon (click = open filter input)
- OR simpler: single click toggles visibility, double-click or right-click opens filter — BUT this is non-discoverable
- BEST approach: Each chip shows its label. If the category is visible and has a filter, show the filter text inline. Below the chip row, show a single filter input for whichever category is "selected" (clicked while visible). Click a visible chip = select it for filtering (show input), click a hidden chip = unhide it.

Actually, simplest and most usable approach:
- Keep chips as toggles for visibility
- Add a single search/filter input to the right of the chips (or below)
- This input has a category dropdown selector (Tools/Agents/Prompts/Model) and a text field
- When the user types, it sets nodeTypeFilters for the selected category
- Active filters shown as small tags/badges below the chips

REVISED simpler approach (consistent with existing UI patterns):
- Each chip is still a toggle button for visibility
- When a visible chip is right-clicked or has a small expand arrow, it reveals a text input inline
- For simplicity and discoverability: add a filter input row below the chip row. Show one compact input per visible category. Each input is labeled (e.g., "Tools:", "Agents:") and filters that category.
- Only show inputs for categories that are currently visible (not in hiddenNodeTypes)
- Inputs are always visible when in session timeline view (no extra toggle needed)

FINAL approach (balancing simplicity and usability):
- Keep filter chips as-is for toggle behavior
- Below the filter chip group, add a compact expandable filter bar
- Toggle its visibility with a small "filter" button or it's always shown
- Show one small labeled input per visible category in a row
- Each input: 120px wide, placeholder text, clears with X button
- This keeps the UI clean while being fully discoverable
