**2. session-discovery.ts — remove 30s idle check (lines 449-452)**

In the `determineSessionState` function, remove the entire block:
```typescript
// 4. If idle for >30s and not detected as waiting, likely completed or stale
if (timeSinceActivity > 30000) {
  return 'completed';
}
```

This block is too aggressive — it marks sessions as completed when they are still actively processing but simply haven't written to the debug log in 30 seconds (e.g., during long tool calls or network requests). The existing checks are sufficient:
- `sessionClosed` (SessionEnd marker in debug log) catches genuinely closed sessions
- `hasCompletionIndicator` catches sessions with summary entries
- Without the 30s check, sessions idle between 10-30s+ that are NOT waiting for user input will correctly remain in 'active' state (the function's default return on line 456)

Also update the comment on line 454 to reflect it is now the fallback for sessions between 5-10s:
```typescript
// Default: if past active threshold and not waiting for user, still consider active
// (might be processing, running tools, etc.)
return 'active';
```
