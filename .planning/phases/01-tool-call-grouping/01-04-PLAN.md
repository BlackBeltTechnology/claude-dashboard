  <action>
Rewrite the `groupConsecutiveToolCalls` function in `client/src/utils/groupingUtils.ts`. The current algorithm requires strict array-adjacency of same-named tools. The new algorithm should group all same-named tool calls within a contiguous "tool run" (a sequence of consecutive tool-type nodes with no non-tool nodes in between).

**Current behavior (broken for real data):**
```
Input:  [Read, Bash, Read, Grep, Read]
Output: [Read, Bash, Read, Grep, Read]  (all singles, all unwrapped — no groups visible)
```

**New behavior:**
```
Input:  [Read, Bash, Read, Grep, Read]
Output: [Read(3), Bash(1→unwrapped to Bash), Grep(1→unwrapped to Grep)]
       = [ToolGroup("Read",3), ToolNode(Bash), ToolNode(Grep)]
```

The new algorithm:
1. Walk the input array
2. When encountering non-tool nodes, push them through unchanged (same as before)
3. When encountering tool nodes, collect the entire contiguous run of tool nodes (all consecutive tool-type nodes regardless of toolName)
4. Within that run, group by toolName: collect all nodes with the same toolName into one ToolGroup
5. Order the groups by the position of their FIRST occurrence in the run (preserves visual ordering)
6. Single-item groups (count === 1) are unwrapped back to plain ToolNode (same as before)
7. Push the ordered groups/nodes to the result, then continue walking

**Full replacement for groupingUtils.ts:**

```typescript
import type { AnyNode, ToolNode, ToolGroup } from 'shared';

/**
 * Groups tool calls of the same type within contiguous tool runs.
 * A "tool run" is a sequence of consecutive tool-type nodes (no non-tool nodes between them).
 * Within a run, all same-named tools are collected into a single ToolGroup.
 * Single-item groups are unwrapped back to the original ToolNode.
 *
 * @param nodes - Array of nodes to process (should be pre-filtered to exclude message nodes)
 * @returns Array with same-type tool nodes grouped within contiguous runs
 */
export function groupConsecutiveToolCalls(nodes: AnyNode[]): (AnyNode | ToolGroup)[] {
  const result: (AnyNode | ToolGroup)[] = [];
  let i = 0;

  while (i < nodes.length) {
    const node = nodes[i];

    // Non-tool nodes pass through unchanged
    if (node.type !== 'tool') {
      result.push(node);
      i++;
      continue;
    }

    // Collect the contiguous run of tool nodes
    const runStart = i;
    while (i < nodes.length && nodes[i].type === 'tool') {
      i++;
    }

    // Now nodes[runStart..i-1] are all tool nodes in this run
    // Group them by toolName, preserving first-occurrence order
    const groupMap = new Map<string, ToolNode[]>();
    const nameOrder: string[] = [];

    for (let j = runStart; j < i; j++) {
      const toolNode = nodes[j] as ToolNode;
      const name = toolNode.toolName;

      if (!groupMap.has(name)) {
        groupMap.set(name, []);
        nameOrder.push(name);
      }
      groupMap.get(name)!.push(toolNode);
    }

    // Emit groups in first-occurrence order
    for (const name of nameOrder) {
      const toolNodes = groupMap.get(name)!;

      if (toolNodes.length === 1) {
        // Single-item: unwrap to plain ToolNode
        result.push(toolNodes[0]);
      } else {
        // Multi-item: create ToolGroup
        const firstNode = toolNodes[0];
        const group: ToolGroup = {
          id: `tool-group-${name}-${firstNode.id}`,
          type: 'tool-group',
          toolName: name,
          nodes: toolNodes,
          count: toolNodes.length,
          state: toolNodes.some(n => n.state === 'active') ? 'active' : firstNode.state,
          timestamp: firstNode.timestamp,
          parentId: firstNode.parentId,
        };
        result.push(group);
      }
    }
  }

  return result;
}
```

**Key differences from original:**
- Collects entire contiguous tool runs, not just consecutive same-name pairs
- Groups by toolName WITHIN a run (handles [Read, Bash, Read] -> Read(2), Bash(1))
- Preserves first-occurrence order of tool names for visual stability
- Single-item unwrapping is integrated into the emit loop (no separate post-processing pass)
- The function signature and return type are UNCHANGED
