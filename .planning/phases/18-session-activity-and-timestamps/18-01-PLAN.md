<task type="auto">
  <name>Task 2: Rework server state detection with 4-state logic and idle_prompt parsing</name>
  <files>server/src/session-discovery.ts, server/src/watcher.ts</files>
  <action>
In `server/src/session-discovery.ts`:

1. Change `ACTIVE_THRESHOLD_MS` from 5000 to 10000 (10 seconds per user decision).

2. Remove `WAITING_THRESHOLD_MS` constant (no longer needed as a separate threshold).

3. Add a new function `hasIdlePromptMarker(claudeDir: string, sessionId: string): Promise<boolean>` that reads the debug log file (`~/.claude/debug/{sessionId}.txt`) and checks if it contains the string `idle_prompt`. This indicates the session is waiting for user input. To avoid reading the entire file every poll, read only the LAST 2000 bytes of the file (use `readFile` with a buffer approach, or read the whole thing — the debug logs are not that large and are already being read for SessionEnd checks).

4. Update `isAssistantWaitingForUser()` to also accept a `hasIdlePrompt: boolean` parameter. If `hasIdlePrompt` is true, return true immediately (this is the strongest signal). Otherwise fall back to the existing check (last assistant message with no tool_use blocks).

5. Also detect `turn_duration` system entries in the JSONL as a secondary "waiting" signal. Add a function `hasTurnDurationEntry(entries: ParsedEntry[]): boolean` that checks the last 5 entries for a `result` type entry (the `type` field in ParsedEntry can be 'result') — this indicates the turn completed and the session is waiting.

6. Rework `determineSessionState()` with this priority order:
   - **Completed**: `sessionClosed === true` OR `hasCompletionIndicator(entries)` => return `'completed'`
   - **Active**: `timeSinceActivity < 10000` (debug log mtime within 10s) => return `'active'`
   - **Waiting**: `isAssistantWaitingForUser(entries, hasIdlePrompt)` is true (either idle_prompt in debug log, or no-tool-use assistant message + turn_duration) => return `'waiting'`
   - **Idle** (default): return `'idle'` — this replaces the current fallback to `'active'`

   The function signature needs a new parameter for `hasIdlePrompt`:
   ```typescript
   export function determineSessionState(
     entries: ParsedEntry[],
     debugLogMtime: number | null,
     fallbackLastActivity?: number,
     sessionClosed?: boolean,
     hasIdlePrompt?: boolean
   ): SessionState
   ```

7. Update `parseSessionFile()` to call `hasIdlePromptMarker()` when `claudeDir` is provided and pass the result to `determineSessionState()`.

8. Remove the `determineSessionStateLegacy()` function if it exists (it's deprecated and no longer needed).

In `server/src/watcher.ts`:

9. Update `pollStates()` to call `hasIdlePromptMarker()` for each session and pass the result to `determineSessionState()`. Since `isSessionClosed()` already reads the debug log, consider combining the debug log reads — read the file once in `pollStates()` and check for both `SessionEnd` and `idle_prompt` markers in the same content string. Create a helper `readDebugLogContent(claudeDir: string, sessionId: string): Promise<string | null>` in session-discovery.ts that returns the full content, then `isSessionClosed` and `hasIdlePromptMarker` can both use it (or just inline the checks in pollStates).

   Optimization: Cache the debug log content read per poll cycle. Read once, check for SessionEnd AND idle_prompt from the same string.

10. In `pollStates()`, the calls to `buildNodes` within individual node state computation pass `determineSessionState([entry], null, entry.timestamp)` — these individual node states are less critical. The session-level state is what matters. Ensure the session-level `determineSessionState` call in `pollStates` includes the `hasIdlePrompt` parameter.
