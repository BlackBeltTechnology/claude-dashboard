  <action>
Fix the session filtering logic in TreeView.tsx so that all sessions display when no session is selected, matching GraphView's behavior.

**Change 1 — Replace the displaySessions computation (lines 271-274):**

Replace the current ternary:
```typescript
const displaySessions = selectedSessionId
  ? filteredSessions.filter((s) => s.id === selectedSessionId)
  : filteredSessions;
```

With a useMemo that matches GraphView's pattern:
```typescript
const displaySessions = useMemo(() => {
  if (selectedSessionId) {
    const selected = filteredSessions.find((s) => s.id === selectedSessionId);
    return selected ? [selected] : filteredSessions;
  }
  return filteredSessions;
}, [filteredSessions, selectedSessionId]);
```

Key difference: When selectedSessionId is set but the session isn't found in filteredSessions, fall back to showing all (instead of empty array). When no session is selected, show all filteredSessions.

**Change 2 — Update the empty state message (lines 276-287):**

Update the empty state conditional to remove the "Select a session" message since TreeView now always shows sessions when they exist:

Replace the empty state block:
```typescript
if (displaySessions.length === 0) {
  return (
    <div style={styles.container}>
      <div style={styles.emptyState}>

            ? 'Session not found'

    </div>
  );
}
```

With:
```typescript
if (displaySessions.length === 0) {
  return (
    <div style={styles.container}>
      <div style={styles.emptyState}>
        {isFiltering
          ? 'No nodes match the current filter'
          : 'No active sessions'}
      </div>
    </div>
  );
}
```

The "Session not found" case is now impossible because displaySessions falls back to all sessions. The "Select a session" case is now impossible because we always show all sessions when none is selected.
