**4. Update enrichedNodes for expanded subagent boxes:**
In the `enrichedNodes` useMemo (around line 133), the existing code enriches `subagent-box` nodes with onToggleExpand and onInternalNodeClick callbacks. When a box is expanded, graphLayout now generates individual RF nodes instead of the box node -- so the enrichment for expanded boxes is no longer needed (the box node won't exist when expanded). The existing enrichment code for collapsed boxes still applies. No changes needed here since the box node simply won't appear when expanded.

However, tool-group nodes generated inside expanded subagents need their click handling to work. The existing `tool-group` click handler in onNodeClick already handles finding tool groups via `findToolGroupInSessions`. For subagent-internal tool groups, the groupId won't match main-session tool runs. We need to handle this:

In the `tool-group` click case, after the existing `findToolGroupInSessions` call, add a fallback that searches subagent sessions:
```typescript

```

Actually, a simpler approach: the graphLayout already sets the `groupId` field on internal tool-group nodes. The `findToolGroupInSessions` function searches subagent sessions recursively. If the tool group isn't found (because the internal node ID doesn't match main-session patterns), create a synthetic tool group from the node data:

```typescript
} else if (node.type === 'tool-group') {
  const foundGroup = findToolGroupInSessions(node.id, node.data);
  if (foundGroup) {
    setSelectedNodeData(foundGroup.toolGroup);
  } else {
    // Subagent-internal tool nodes: search for tool by original node ID across all sessions
    const searchForToolInSubagents = (): AnyNode | null => {
      const searchSession = (session: Session): AnyNode | null => {
        for (const sub of session.subagents) {
          for (const n of sub.nodes) {
            if (n.type === 'tool' && n.id === (node.data as any).groupId) return n;
          }
          const nested = searchSession(sub);
          if (nested) return nested;
        }
        return null;
      };
      for (const session of sessions) {
        const found = searchSession(session);
        if (found) return found;
      }
      return null;
    };
    const toolNode = searchForToolInSubagents();
    if (toolNode) {
      setSelectedNodeData(toolNode);
    }
  }
}
```

Update the TreeView's `selectNode` callback to navigate to individual internal RF nodes when clicking on nodes inside a subagent, instead of always focusing the box node.

**Current behavior (line 173-202):**
When `parentSubagentId` is set and a node is clicked:
1. Expands the parent subagent box
2. Focuses the box node: `createNodeId(selectedSessionId, ${parentSubagentId}-box)`

**New behavior:**
When `parentSubagentId` is set and a node is clicked:
1. Expand the parent subagent box (unchanged)
2. Focus the INTERNAL RF node, not the box:
   - For the synthetic request/response message nodes (IDs like `${subagentId}-request`, `${subagentId}-response`):
     Build graph node ID as `createNodeId(selectedSessionId, node.id)` (the ID already includes the subagentId prefix)
   - For tool/skill/message nodes inside the subagent:
     Build graph node ID as `createNodeId(selectedSessionId, `${parentSubagentId}-${node.id}`)`
     This matches the pattern used by graphLayout.ts when generating expanded internal nodes

Update the selectNode callback:
```typescript
if (parentSubagentId && selectedSessionId) {
  // Expand the parent subagent box so RF nodes are generated
  expandAllSubagentBoxes(selectedSessionId, [parentSubagentId]);

  // Build the graph node ID for the internal RF node
  // Request/response nodes already have the subagentId prefix in their ID
  const nodeId = 'type' in node ? node.id : '';
  const isRequestOrResponse = nodeId.startsWith(parentSubagentId + '-request') ||
                               nodeId.startsWith(parentSubagentId + '-response');

  let graphNodeId: string;
  if (isRequestOrResponse) {
    // IDs like "${subagentId}-request" or "${subagentId}-response"
    graphNodeId = createNodeId(selectedSessionId, nodeId);
  } else {
    // Tool/model/other nodes: prefix with subagentId
    graphNodeId = createNodeId(selectedSessionId, `${parentSubagentId}-${nodeId}`);
  }

  setFocusedNode(graphNodeId);
}
```

This ensures that clicking a tree node inside a subagent:
1. Expands the box (triggering graphLayout to generate RF nodes)
2. Focuses the specific internal RF node (fitView zooms to it)

The small delay in GraphFocusHandler (100ms setTimeout) already accounts for layout recalculation after expand state changes, so the focus will work after the expanded nodes are rendered.
