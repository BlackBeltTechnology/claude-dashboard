  **The Problem:** When a user clicks a node inside a subagent session in the tree view, `selectNode` calls `setFocusedNode` with a graph node ID like `"parentSessionId-childNodeUuid"`. This ID does NOT exist as a React Flow node because subagent children are internal data inside SubagentBoxNode, not separate RF nodes. The focus/navigation silently fails.

  **The Fix in TreeView.tsx:**

  In the `selectNode` callback (~lines 172-195):

  1. Import `toggleSubagentBox` from the session store (add to the existing store selectors at the top of the component).

  2. Import `selectedSessionId` from the store if not already available (it should already be used).

  3. When a node is clicked and it has a `type` field (meaning it's a data node, not a session node), check if this node belongs to a subagent session. To detect this:
     - The tree view renders subagent children inside subagent session sections. The parent subagent session has a short ID (length < 20).
     - When `selectNode` is called for a node inside a subagent, we need to know which subagent it belongs to. The tree view should pass the parent subagent session ID as context.

  The cleanest approach: Modify the `selectNode` callback to accept an optional `parentSubagentId?: string` parameter. When rendering subagent session children (in the tree view's rendering logic), pass the subagent session ID as this parameter.

  4. When `parentSubagentId` is provided:
     a. Call `toggleSubagentBox(selectedSessionId || '', parentSubagentId)` to ensure the parent box is expanded. But `toggleSubagentBox` toggles -- we need to ensure it's EXPANDED, not toggled. Instead, use the store's `expandAllSubagentBoxes(selectedSessionId || '', [parentSubagentId])` which sets (not toggles) the expansion state. Import this action.
     b. Compute the box node graph ID as `createNodeId(selectedSessionId || '', parentSubagentId + '-box')` -- this is the actual React Flow node ID for the SubagentBoxNode.
     c. Call `setFocusedNode(boxGraphNodeId)` to navigate the viewport to the subagent box.
     d. Optionally also call `setSelectedNodeData(node)` to open the detail panel for the clicked node (if the node is a tool node with data).

  5. When `parentSubagentId` is NOT provided (regular session nodes), keep the existing behavior unchanged.

  **Passing parentSubagentId through the render tree:**

  In the tree view's rendering logic, wherever subagent children are rendered (look for where subagent.nodes are iterated/mapped), pass the subagent's ID through the render hierarchy to `selectNode`. This likely involves:
  - Finding where subagent sessions' child nodes are rendered (look for references to subagent nodes in the renderNode or TreeNode callbacks)
  - Adding the subagent ID as context that flows to the `selectNode` call

  Look at how the TreeView currently renders subagent sessions. The `renderNode` function and `TreeNode` component likely have an `onSelect` callback. Thread the `parentSubagentId` through this callback chain.
